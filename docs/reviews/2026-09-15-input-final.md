# 输入与阻断交互最终审计

本轮接续 [第二轮交互审计](2026-09-14-followup-audit.md)，遵循既有
[TasteSkill / 21st.dev 前端基线](../frontend-baseline.md)。范围是连接、输入与命令、审批、结构化提问、嵌套弹层、Settings 和会话链接的操作边界。

## 确认并修复的问题

| 问题                                   | 实际复现                                                                                               | 修复与验证                                                                                                                                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 审批把浏览器快捷键当作决定             | 聚焦审批后按真实 `Ctrl+Y`，立即发出 `approval/respond` 并关闭审批。组合输入产生的 `y` 也能走相同回调。 | 审批快捷键排除 Ctrl、Meta、Alt、`isComposing` 和 IME 的 `keyCode 229`。修饰键及组合事件不发送决定；普通 Y 仍恰好发送一次。                                                                              |
| 短屏连接页无法滚到 Connect             | 320×320 中输入字段可操作，但滚轮滚到底后 Connect 顶端仍在 y=381，处于视口之外。                        | 连接入口拥有受限纵向滚动，并采用安全居中。实际滚动后可点击 Connect；认证失败后修改 token 并重试成功。连接表单的 IME Enter 也统一覆盖 229。                                                              |
| 长选项撑宽整组问题                     | 三个问题中的长无空格选项使 Other 输入框右边界达到 x=1095，视口只有 320px。                             | UserQuestionPanel 使用局部 Grid 最小列约束、flex 子项最小宽度和任意位置换行。手机输入保持 16px。单选、多选、自由文本和 Continue 都落在视口内，第一次响应失败后保留所有答案，重试发送相同内容。          |
| radio 组可突破模态焦点边界             | 选中第二个 Full 选项后按 Shift+Tab，焦点离开提问弹窗，落在底层对话的 Shiki 代码 `<pre>`。              | ModalSurface 根据 name/form 将 radio 组视为一个 Tab 停靠点，优先使用已选项；排除负 tabindex。选中项与 Continue 之间正反向循环，ArrowUp 改变选择后仍正确。                                               |
| 手机内部菜单的 Escape 提前关闭整个抽屉 | 阅读审计发现共享 capture listener 在搜索框和菜单的 React 回调之前处理 Escape。                         | Tab 继续在 capture 阶段维护边界；Escape 在 bubble 阶段处理并尊重 defaultPrevented/stopPropagation。先关闭搜索或菜单、恢复其按钮焦点；下一次 Escape 才关闭抽屉。嵌套 Diff 与审批的既有分层行为继续通过。 |

没有为通过检查提高资源预算，也没有改变审批决定、命令分发、队列或服务器状态的含义。

## 实际操作验证

新增 [final-input.spec.ts](../../e2e/final-input.spec.ts) 的七个 Chromium 场景：

- 审批修饰键、IME 与一次普通快捷键决定。
- 320×360 长审批正文实际滚轮阅读、四个操作按钮逐一聚焦与可达性。
- 320×320 连接入口实际滚动、错误 token、修正后重试。
- 320×360 三个长问题、单选/多选/自由文本、失败保留及相同答案重试。
- 命令列表中的 IME 方向/确认事件、Escape、选择替换后的 Alt+Enter /
  Ctrl+J、最终恰好一次发送。
- radio 组的 Shift+Tab / Tab / ArrowUp 焦点边界。
- 手机抽屉中搜索和视图菜单的 Escape 层次、焦点恢复。

同时重跑原有 modal-stack、settings-mobile、session-links 浏览器场景，覆盖折叠文件、嵌套审批与 Diff、provider 删除确认、手机设置实际滚动、链接打开失败/重试和复制拒绝。

最终局部浏览器批次 **21 项全部通过**，耗时约 1 分钟；相关组件与链接单元测试共
**31 项通过**，Web TypeScript 和所改 TS/TSX 的定向 lint 通过。记录位于
`/tmp/octos-final-input-verified.log`。之后仅调整提问错误文案的内边距与语义文字色，并重新通过该浏览器场景。

## 边界

浏览器测试使用项目锁定的 Playwright
Chromium、独立本地 fixture 与测试凭据。没有读取真实 token、连接线上服务、改变用户会话或使用真实模型。IME 事件通过浏览器 KeyboardEvent 的组合标志及 229 注入；不宣称已验证某款操作系统输入法。320×320
/ 320×360 是可用高度缩短的浏览器近似，不等同于物理手机、iOS
Safari 或真实软键盘。

临时测试端口为 54222 / 55222，由 Playwright 托管并在结束后清理；原有 44174 /
54080 服务保持不变。全仓库最终检查和生产构建结果由最终整合报告记录。
