## 仍需记录的体验边界

这些不是“已修完”的承诺，也不列成此次遗漏 bug：

1. **缺乏可证明的工具身份时仍保留信息。**
   没有唯一 thread→turn 映射、同 turn 多次相同输出或多对一候选时，前端不能安全确定哪个输出属于哪个调用。仍可能显示独立输出/调用；要完全消除该情况，Core 需在持久化工具消息中提供 tool-call
   identity。
2. **Core 迟发用户消息仍存在。**
   一轮只有原提问的普通旁观顺序已改善；同轮 steer 可能先于原问题持久化，且 canonical
   UserMessage 不保证携带可区别原问题的身份，前端不能凭文本猜完整语义。所有正文保留，进一步完善需要协议配合。
3. **新标签页的历史范围由服务器能力决定。** 不支持完整 session
   listing 的服务器只能展示本标签页确认过的会话；现在搜索准确说明范围。前端不会编造完整历史。
4. **刷新活跃工作仍受 Core 连接生命周期限制。**
   离开警告会保护正在执行的工作；持久运行与重新附着需要 Core 支持。整页刷新也不会保存未发送草稿。
5. **已失败的懒加载代码块仍可能需要 Reload app。**
   现有 SurfaceBoundary 保留其他区域、草稿与 Stop，并提供退出和明确重载说明；同一个失败 import 的原地重试不是本轮承诺。
6. **折叠尺寸动画按浏览器能力渐进增强。**
   Chromium 支持平滑展开；Firefox/WebKit 即时展开仍可键盘操作。减少动态效果设置始终优先。

7. **流式 Markdown 的阅读细节仍可改善。**
   目前流式正文以纯文本更新，完成后应用 Markdown 排版；首次加载解析模块也可能短暂显示纯文本。渐进排版、代码边输出边高亮是后续体验优化，应同时保持长帧预算和阅读锚点。

真实手机软键盘、真实 IME、辅助技术朗读及用户第 75 百分位性能不在自动化模拟覆盖范围。实验室 CLS 为零不能证明任何加载布局都合理，因此此次直接对比了加载前后矩形。
