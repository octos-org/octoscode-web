## 唯一发布前修复建议：已完成会话恢复后的工具时间线

这是用户可重复观察到的差异，不依赖共享工作区的后续修改。

**复现 A：刷新。** 在真实会话 `da9c52bb` 请求仅执行 `pwd` 和
`git status --short`，等待最终回复。刷新前顺序是：

```text
用户请求 → Thought process → bash → bash → Thought process → 最终回复
```

在 `06:34:37` 刷新后，以及 `06:35:22` 第二次刷新后，顺序变成：

```text
用户请求 → Thought process → Tool output → Tool output
→ Thought process → 最终回复 → bash → bash
```

折叠条目从 4 个变成 6 个。内容未完全丢失，但原来一个工具条目的调用名称和输出被拆开，调用还移到了最终回复之后。继续正常追问时，这些孤立调用也可能继续留在新回复后面。

**复现 B：切换会话。** 新真实会话 `97d1e3ca` 只读取根
`package.json`，最终回复提供中文运行说明与四个代码块。即时视图中的 `read_file`
位于最终回复前；切换到另一会话再回来后，原位是 `Tool output`，`read_file`
出现在最终回复后。新浏览器通过会话链接打开，也得到相同恢复视图。

这会影响用户对“执行了什么、输出属于哪次执行、何时得到最终结论”的判断。建议把**恢复前后保持工具调用/输出关联与相对位置一致**作为唯一发布前优先修复和验收目标。不要仅因两个输出文本相同就进行消重；具体关联方案应由代码/协议审计根据权威身份字段确定。

证据：

- `09-live-tool-expanded.png`：第一轮完成后的即时视图。
- `11-live-after-refresh.png`：刷新后的拆分与后置调用。

- `35-shared-live-conversation.png`：另一个浏览器恢复同一任务后的视图。
- `live-hydrate-tool-redacted.json`：仅两条 tool message 的
  `seq/turn_id/content` 与对应 replay tool_end 的身份和输出预览。
- `live-hydrate-identities.json`：仅 messages/turns/threads/replay 的关联字段，原始字段不存在时明确为
  `null`。

浏览器侧取得的两条持久化 tool message 没有 `turn_id`；对应 replay tool_end 有
`turn_id/tool_call_id`，且输出预览与 message 内容一致。这能证明恢复视图的差异，不能单靠文本相等证明安全的关联算法。

## 独立观察：跨窗口入站消息晚于回答

两个独立浏览器上下文通过同一会话链接打开真实会话。在第二个窗口发送正常中文追问，发送窗口显示“用户→回答”，旁观窗口能同步收到，但第一轮显示“回答→用户”。第二轮较短追问显示 reasoning 在用户消息前、最终回答在后；第三轮固定标记又显示“回答→用户”。

第三轮只记录了通知时间、类型、序号和身份字段，**不保存通知正文或连接 URL**。同一 turn 的 canonical 入站序列为：

| 类型                | seq   | 浏览器接收时间 UTC  |
| ------------------- | ----- | ------------------- |
| reasoning_delta     | 1–17  | 06:57:27.568–27.585 |
| assistant_delta     | 18–22 | 06:57:27.586–27.590 |
| user_message        | 23    | 06:57:27.592        |
| assistant_persisted | 24    | 06:57:27.594        |
| turn_terminal       | 25    | 06:57:27.599        |

因此这一轮浏览器的后置用户消息与入站顺序一致。**这是独立的产品/协议顺序观察，不能写成前端把正常序列重排，也不能直接并入上面的 hydrate 关联根因。**
本审计没有继续追查 Core 实现。

证据：`38-live-observer-message-order.png`、`39-live-sender-message-order.png`、`43-live-final-observer.png`、`observer-envelope-metadata.json`。
