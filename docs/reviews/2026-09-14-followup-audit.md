# 第二轮交互与恢复修复

本轮接续[第一轮审计](2026-09-14-product-audit.md)，重点实际操作中的阻塞和状态不明时的恢复。TasteSkill/21st.dev 的[前端基线](../frontend-baseline.md)继续适用。

## 修复范围

- **回合恢复不能凭缺失记录推断没有执行。**
  原逻辑把超时后 hydrate 不含该回合视为安全重发依据；固定 rc.9 的实际契约不支持这个结论。现在用能力协商后的
  `turn/state/get`
  查询确切回合。`unknown`、查询失败和不支持查询保持不确定状态；明确 active/interrupting 恢复观察，明确终态结算队列。旧请求回包不能影响新会话或新回合。详见[恢复报告](2026-09-14-turn-recovery.md)。
- **等待不再只有无法解释的 Working。** 状态不明时显示恢复提示和 Check
  status；草稿可编辑，排队消息可移除，发送暂停。恢复提示位于可滚动的对话区，避免挤出手机输入框。
- **长中文队列使手机输入区撑宽。**
  320×480 下队列和输入宽达 768px，删除按钮被裁切；body 隐藏溢出让文档宽度检查漏掉了问题。修正对话 Grid 的列约束及 composer、queue 的最小宽度，以控件边界作为回归依据。
- **窄屏设置页底部操作不可达。** 内容 flex 项缺少
  `min-height: 0`，实际超出被裁剪的对话框。恢复内部滚动，General 和 Models 的底部操作、关闭按钮均可到达。
- **嵌套弹窗的 Escape 穿透导致误中断。**
  审批中的 Diff 与底层审批同时处理按键。现在仅顶层 ModalSurface 捕获 Tab/Escape；关闭 Diff 不发送 interrupt，下一次在审批内按 Escape 才执行对应操作。原生 summary 纳入键盘序列，设置内的删除确认也使用同一弹窗机制。
- **审批或提问结束后键盘输入丢失。**
  旧输入框移除后焦点落到 body。输入行为抽到按需加载的 PromptComposer，桌面重新挂载时恢复输入焦点；移动端回到 composer 容器，避免自动弹出软件键盘。关闭 Settings 仍恢复原触发按钮。
- **保存链接在新浏览器中无效。**
  原实现只寻找当前标签页已缓存的导航引用。现在未知引用在认证后展示目标服务器和工作目录，明确点击后才打开；校验工作目录/Profile/Session 回显后提交。固定 rc.9 对不存在 ID 可能创建空会话，因此不会把一次 open 表述为找到了已有历史。详见[链接报告](2026-09-14-session-links-audit.md)。

- **变更操作挤掉手机项目名。** 生产录像发现出现 Review
  changes 后标题只剩几字；同时旧全局样式覆盖了手机顶部的间距规则。手机入口改成同一线性图标族的 44×44px
  Diff 按钮，保留完整无障碍名称，修正响应式样式优先级。390px 和 320px 下同时验证项目名可用空间、按钮触达、打开审查和 Escape 返回焦点。
- **刷新恢复与外部链接不再重复打开。**
  同一个当前会话只走一次恢复；失败后保留认证并返回工作目录选择。不同的保存链接优先于旧标签页选择，先认证，再确认目标，不会先打开旧会话。
- **状态不明仍可以主动退出连接。** 原 General
  settings 在任何活动回合期间都禁用 Disconnect，导致不支持状态查询时无可用操作。现在可发起 Disconnect/Forget，先说明运行任务可能停止、队列丢弃，再明确确认；Cancel 保留当前工作和队列。
- **复制反馈与实际结果一致。**
  会话链接和诊断复制都等待剪贴板操作成功后才显示 Copied；链接复制被拒绝时提供已选中的只读文本，诊断复制失败时显示可重试错误。

## 首屏与结构

PromptComposer、SessionSidebar 和手机导航弹层按需加载。可选 RPC 响应解码与同步事件校验拆开，防止任务、模型、hydrate 的整个解析模块重新进入初始加载图。请求仍立即发送；解码器加载失败或无效响应仍拒绝，不能产生假成功。352
KiB 初始 JavaScript 和 80 KiB 初始 CSS 的原预算保持不变。

[浏览器操作报告](2026-09-14-browser-usability.md)记录原始控件几何、焦点轨迹和 Escape 所触发的 RPC；[前端基线](../frontend-baseline.md)已经补充这些验收条件。

## 验证边界

浏览器回归使用受控 fixture 验证不利时序和真实键盘、滚动、焦点行为。独立 rc.9 检查证明了
`turn/state/get`
的实际 unknown 响应，以及保存的完整引用在连接关闭、Core 重启后可重新取得已有记录。

这些修复没有增加脱离浏览器持续运行的服务端机制，也没有把 unscoped `session/list`
当作可靠历史目录。未知回合仍须保留不确定性；应用不会为了解除等待而自动重发。
