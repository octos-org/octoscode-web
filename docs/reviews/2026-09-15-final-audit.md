## App 失败隔离与命令修复

在前一轮生产快照上主动让 Settings
JavaScript 返回 503：全局 FatalErrorBoundary 会卸载
`useOctosSession`，已打开的 owner
socket 数量随关闭增加，输入框和 Stop 同时消失。这是此次实际复现的运行中断风险，而非纯提示文案问题。

新增 `SurfaceBoundary`
保留上层会话运行时。设置、工作目录、Diff 和任务弹窗在加载时有可取消的焦点边界，失败时可以关闭。审批、问答和输入视图失败时保留能力允许的 Stop。错误状态按会话或交互请求分隔，避免一个失败视图影响新会话或下一条交互。真正的全局错误提示也改为准确说明连接关闭可能停止运行，不能声称刷新安全且只丢失未发送文字。

React.lazy 会缓存已拒绝的导入，因此没有添加无效的 Retry。Reload
app 明确提示可能停止任务并丢弃草稿和队列，现有 beforeunload 保护仍在。一个模块失败不会自动刷新、重发模型请求或关闭连接。

本地命令展示移至独立模块，`prompt` 和 `interrupt`
保持原来的立即调用，命令分类仍在发送前同步完成。模块加载失败会给出提示并在输入尚空时恢复原命令，绝不降级成模型输入。`/copy`
的 Promise 和 React updater 都检查原会话身份。

## 性能与构建

新的可靠性代码最初把初始 JS 推至 363,420 字节，超过原有 352
KiB 门禁。没有提高预算。除命令展示按需加载外，查明 Rolldown 因共享协议常量、同步 token-cost 事件与 workspace 响应解析的 re-export 边，将原本按需加载的响应块重新拉入初始图。将这些共享边固定到既有 protocol-values 组，恢复原有响应加载边界。没有改动 RPC 发送时机。

最终初始 JS **360,311 / 360,448 字节**，CSS **67,057 / 81,920 字节**，全局 CSS
**2,864 /
2,877 行**。JS 仅剩 137 字节余量；后续功能需要继续维护真实加载边界，不能靠提高预算掩盖增长。此统计只包含初始资源，进入各功能后仍会加载对应模块。

## 仍然存在的边界

- 刷新或关闭 owner 连接后保证任务继续运行、完成 owner 的安全释放，以及完整跨浏览器会话目录，仍取决于 Core 的契约；本轮没有伪造这些能力。
- `Show earlier messages`
  只展开服务器已经发送到浏览器的记录；不是未提供历史的远程分页。它限制初始 DOM，尚不是无限历史虚拟列表，完整展开会增加内存与节点数。
- 自动化与 Chromium 本地采样不能证明所有真实手机、浏览器、网络和模型组合都无缺陷。需要上游能力或部署实测的事项没有被标记为前端已解决。

`.octos/`、`.octos-workspace.toml` 未改动。合并状态以对应 GitHub PR 和 `main`
