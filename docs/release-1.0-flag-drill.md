# octoscode-web 1.0 flag 演练清单

演练指的是：在**指定的体验环境**里，用**一个测试浏览器**打开双模式 flag，按本清单冒烟，再把 flag 关回去，并留下证据。演练不改 flag 的默认值，不对其他用户开放，也不等于发布 1.0。本清单只写步骤和预期，实际执行由后续任务做。发布说明草稿见
[release-notes-1.0-draft.md](release-notes-1.0-draft.md)。

全程遵守：

- 只用执行任务指定的环境和测试账号，不碰别人的实例或生产数据；不把令牌、API
  key 写进截图、日志或证据。
- 真实模型的轮数按任务给的预算控制，记下实际用了几轮。
- 某一步结果和“预期”不符时，先按第 10 节关回 flag，再记录，不在现场改代码或配置。

## 0. 开始前：前提核对

任何一项不满足就**不开 flag**，只记录原因。

| 项目               | 怎么核对                                   | 通过的标准                                                                                                                                                               |
| ------------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 内核版本           | `GET /health` 的版本串；对照 commit 历史   | 包含 octos#3255、#3256、#3284、#3285                                                                                                                                     |
| 网页请求了对话能力 | 打开会话时的协议握手 / `session/open` 回复 | `capabilities.supported_features` 同时有 `session.work_mode.v1` 和 `session.chat_workspace.v1`；`supported_methods` 有 `session/chat/create` 和 `permission/profile/set` |
| 安全复审           | T-0623 的结论                              | 可通过（APPROVABLE），没有未关闭的 P1                                                                                                                                    |
| 环境               | 执行任务的说明                             | 是指定的体验环境，不是共享生产或别人的体验站                                                                                                                             |
| 浏览器             | 准备两个独立的浏览器上下文                 | 桌面 1440×1000；手机 390×844，开触摸                                                                                                                                     |

## 1. 记录版本和资产（开始和结束各一次，两次必须一致）

- 内核：`GET /health` 的完整版本串。
- 网页：`GET /octoscode-web-build.json` 的 `release`、`source_revision`
  和内核 revision；`index.html` 引用的入口脚本文件名及其 SHA-256。本地构建只会写
  `dev` / `unknown`，这时以资产哈希为准，并在记录里写明。
- 能力：第 0 节看到的 `supported_features` 和 `supported_methods`。
- 浏览器名称和版本、视口、界面语言。
- 都写进 `versions.json`。

## 2. 打开 flag

- 位置：**只在测试浏览器里**设置 `localStorage` 键 `octoscode-web.two-modes` 为
  `on`，然后**重新加载**（页面加载时才读这个值）。控制台写法：
  `localStorage.setItem('octoscode-web.two-modes', 'on'); location.reload()`。服务器上没有对应开关；内核按每个连接请求的能力协商。
- 预期：侧栏出现“工作模式”分组（中文“编码 / 对话”，英文“Code /
  Chat”），“对话”可以点。
- 如果“对话”不可用并显示“对话需要服务器为每个对话单独分配文件夹，这台服务器还不支持。”，说明前提不满足：截图后直接做第 10 节。

## 3. 普通用户冒烟：编码（开 flag 前做一次，开后再做一次）

| 操作                             | 预期                                                  |
| -------------------------------- | ----------------------------------------------------- |
| 连接，选一个测试文件夹，新建会话 | 和 v0.22 相同；没有对话专用的界面                     |
| 发一条会改文件的小请求，走完审批 | 这一轮正常结束；摘要列出改动的文件                    |
| 打开会话面板                     | 有“概览 / 文件 / 改动 / 产物”四个标签；改动能打开差异 |
| 刷新页面                         | 会话、模式和选中项恢复；不出现“另一个客户端”          |

开 flag 前后结果应当相同。

## 4. 对话：默认只读、禁网

| 操作                                      | 预期                                                                                               | 证据                                                  |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 切到“对话”，新建对话                      | 没有文件夹选择器；输入栏显示只读（Read only）和禁止联网（Network blocked）；服务器确认之前不能发送 | 截图；协议里这个会话的权限设置为 `read_only` + `deny` |
| 用一个通用模板（如周报）发一条            | 回答以内联 Markdown 显示；“产物”为空；没有写文件                                                   | 截图                                                  |
| 看 `session/open` 回复的 `workspace_root` | 是服务器分配给这个对话的文件夹，不是共享目录或测试文件夹                                           | 记录路径                                              |

## 5. 对话：允许文件产出 → 产出 → 撤回

| 操作                     | 预期                                                                                           | 证据                     |
| ------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------ |
| 点“允许文件产出”         | 只发出一次权限设置：同一会话、`workspace_write` + `deny`；服务器读回后显示“文件产出已开启”     | 协议帧（抹掉令牌）；截图 |
| 请它把刚才的内容存成文件 | 文件出现在“产物”里，能预览和下载；下载内容与服务器上的文件逐字节相同                           | 下载文件和 SHA-256       |
| 点“关闭文件产出”         | 发出一次 `read_only` + `deny`；标签回到“允许文件产出”；已有文件仍可查看                        | 协议帧；截图             |
| 关闭后再请求写文件       | 写入被拒（在回答或折叠的执行状态里可见）；对话里不出现“切到写入并继续”，不自动提权、不打开网络 | 截图                     |

## 6. 失败与恢复

| 情形                                                       | 预期                                                                                     |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 一轮进行中刷新页面                                         | 这一轮继续或如实显示状态；对话模式、选中的对话和权限状态从服务器读回，不重复发送权限设置 |
| 短暂断网再恢复                                             | 显示“正在重新连接”，恢复后状态与服务器一致                                               |
| 权限设置出错（自然出现时才记录；不要在真实环境里人为注入） | 显示错误；只发一次，不自动重试；“重新读取服务器的权限”按服务器当前状态恢复               |
| 内核重启（环境允许时）                                     | 对话的权限保持最后一次服务器确认的状态（只读或已开启），网络仍禁止                       |

## 7. 编码对照

- 从对话切回编码：回到之前选中的编码会话；编码会话的权限和网络设置没有被对话改动。
- 两个对话互相看不到对方的产物；用 B 对话下载 A 对话的文件被拒绝。
- 如果环境里有根目录在数据目录之上的编码工作区：它读不到、列不出、发送不了任何对话文件夹里的文件。没有这种工作区就写“未覆盖”。

## 8. 手机和中英文

- 手机 390×844：在抽屉里切换编码和对话；手机自己的对话里，首页、文件产出按钮（点击区域不小于 44px）、产物抽屉和下载都能用；页面没有横向滚动。用手机遥控别处的对话时不显示文件产出按钮（手机不能放宽权限），这是预期。
- 中文和英文各走一遍第 4、5 节的关键屏，文案和按钮名称与界面语言一致。

## 9. 权限和网络（贯穿全程）

- 对话发出的每一次权限设置都是 `deny`
  网络，从不出现完全访问；会话 id 与当前对话一致。
- 切换模式、选择模板都不发送权限设置。
- 对话里没有对外网络请求。

## 10. 关回 flag 与回滚

- 关回：在同一个浏览器执行
  `localStorage.removeItem('octoscode-web.two-modes'); location.reload()`。预期：“工作模式”分组消失，编码会话照常；服务器上的对话保留，**不删除**。会话引用存在标签页里，所以同一个标签页里打开过的对话还会作为普通会话列在它的文件夹下，关掉标签页或“忘记服务器”后才消失。记录实际看到的情况。
- 出现问题时：立即按上面关回，再记录。如果是网页构建本身有问题，按
  [Releasing](releasing.md)
  回到上一个不可变的发布包；不迁移、不删除服务器上的会话或对话。内核的回滚不在本清单范围内，只记录。
- 关回后再做一次第 3 节，确认编码模式不受影响。

## 11. 证据

- 每次演练一个目录，内含：开始和结束的
  `versions.json`；每步截图（文本里抹掉令牌和 key）；关键协议帧；下载的文件和 SHA-256；一张“步骤 → 预期 → 实际 → 证据文件”的汇总表。
- 写明没覆盖的部分（例如没有实体手机、Safari 或内核重启）。
- 结束时关闭测试浏览器上下文，记下保留或删除了哪些测试对话；对所有证据做一次凭据扫描。
