## 编码和对话两种模式

- 侧栏顶部可以在**编码**和**对话**之间切换（英文界面为 Code /
  Chat）。两种模式各自列出自己的会话，切回来时回到之前选中的那一个；手机抽屉里同样可以切换。切换本身不改任何权限。
- **编码**就是现在的产品：选择服务器上的文件夹，按原有权限和审批改文件，会话面板的概览、文件、改动、产物四个标签照旧。没有内核支持或没打开 flag 时，只有编码模式，和 v0.22 一样。
- **对话**用于周报、资料整理、演示提纲这类不需要选文件夹的工作：首页只显示通用模板，回答优先，执行过程收成一行状态，右侧面板只有“产物”。每个对话由服务器分配一个只属于它的文件夹，网页不选、也不显示文件夹路径。
- 服务器不支持“每个对话一个文件夹”时，对话按钮不可用，并说明“对话需要服务器为每个对话单独分配文件夹，这台服务器还不支持。”网页不会退回共享文件夹去假装可用。

## 对话里的文件产出：明确允许，可以撤回

- 新对话默认**只读、禁止联网**。服务器确认这个默认值生效之前不能发送；答案先以内联形式留在对话里。
- 要让 Octos 把文件存下来，点“允许文件产出”。网页通过已有的
  `permission/profile/set`
  把这一个会话改成“可写本对话文件夹、仍然禁网”，并从服务器读回确认后才显示“文件产出已开启”。不是逐个文件授权，也不会顺带打开网络或完全访问。
- 产出的文件出现在“产物”里，可以预览和下载。点“关闭文件产出”回到只读；已经产出的文件仍可查看。
- 权限修改失败时显示错误，只发送一次、不自动重试；“重新读取服务器的权限”可以按服务器当前的状态恢复显示。权限是完全访问等其他组合时，网页不提供这个开关，也不改它。用手机遥控别处的对话时也不提供这个开关。对话里写入被拒时，不会像编码模式那样提供“切到写入并继续”，放宽权限只能通过这个开关。

## 权限与共享边界

- 两种模式共用同一个连接和账号、Profile 的模型设置、显式保存的记忆、已安装的技能和已配置的连接器。对话的整段内容不会被隐式写进记忆。
- 草稿、审批、队列和对话记录严格按会话隔离。
- 对话的文件夹是本地文件的边界：其他对话和编码会话读不到它，下载也只给拥有它的对话（由 octos#3256 在内核里保证）。连接器、MCP 等外部来源仍按各自的授权和网络策略工作，对话的文件夹不是它们的隐私边界。
- 网络不会因为切换模式、选择模板或允许文件产出而打开。

## v0.22 之后的重要修复

- 断线重连后，本标签页发起的一轮仍算作本页的，刷新后不再误报“另一个客户端正在此会话中工作”（#451）。
- 同一轮里写入又发送的文件，在对话里只显示一张卡（#454）；完成摘要和产物计数也只算一个，产物页仍在“写在工作区里”和“发给你的”下各列一次，发送那一行标“也写在工作区里”（#456）。
- 记忆的三种入口分别说明去向和在哪里能找到（#453）。
- 技能审查页不再前后矛盾：安装这一步不运行任何东西，装好以后 Octos 用到这个技能时可以在服务器上运行它的代码；安装被拒时不再留着上一次的“已安装”提示（#452）。
- 对话的文件产出开关使用产品按钮样式，手机上点击区域至少 44px（#457）。
- 权限设置尚未被服务器确认（或结果不明）时，派发闸挡住所有发送入口；必须先重新读取服务器权限，权限设置不会自动重发（#463，修复 T-0623 发现的 P1）。
- 刷新后切回编码或对话，能按服务器最新列表恢复各模式上次选中的会话；目标已不在时如实说明（#464，修复生产体验发现的 P2）。

## 内核要求（发布时按实际版本填写）

- 编码模式的要求与 v0.22.0 相同：最低支持 octos
  `v2.0.3`，新能力按服务器声明出现。
- 对话模式需要包含上述发布前提的内核版本。具体标签或 commit 在发布前按实测填写，不预先写死。

## 已知限制（开放前需要复核）

- 对话全流程除协议夹具外，已在按 main 构建的隔离真实内核上走通（文件真实写入、撤回后真实拒绝、文件夹互不相串；见 T-0622 生产体验），权限安全也经独立复验（T-0667
  APPROVABLE）。这些都用确定性桩代替真实模型，**不证明真实模型的产出质量**；真实模型上的小规模核对仍是发布前待办。
- 体验第 5 轮的 F-01（对话不可用）已随 T-B 合入和 T-0635 能力接线消除；生产体验的 F-01（切回编码不恢复会话）已由 #464 修复。
- 对话需要的内核能力尚未进入任何已发布的内核版本；正式发布前必须按实际部署版本重新核对「内核要求」。
- 对话的来源输入沿用已有的附件能力：文本粘贴，以及图片、Markdown、CSV、PDF；Office 文件不支持；默认不开放网络连接器。
- 部署出来的网页如果用本地构建，`octoscode-web-build.json` 只会写 `dev` /
  `unknown`，只能靠资产哈希确认版本（体验第 5 轮记录）。正式发布要用带标签的构建。
- 默认技能来源仍然只能审查、不能安装，原因会在页面上写明（体验第 5 轮 F-02）。
